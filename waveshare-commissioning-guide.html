The zero battery-version field neither proves absent BMS communication nor identifies battery firmware. Protocol 0201 is not a register address, baud rate or proof of decoding scale. Do not substitute a profile for another model merely because its MAIN version matches.

Logic decision: retain the existing read-only decoding candidates and PowerFlo freshness/unknown-state safeguards. Do not auto-select scales, status bits or relay meanings from this firmware string. Obtain the manufacturer's exact register sheet or timestamp-matched raw-register/display readings for static, charging and discharging states, then validate SOC, V/A/W, grid import/export, protected load and each installed MPPT. Leave uncertain optional fields unmapped. Repeat the comparison after inverter firmware changes; do not request another screenshot as a substitute for live evidence.

1. Understand the data path

The board is a programmable ESP32-S3, not an Ethernet Modbus gateway. Install ESPHome, use its native API over Wi-Fi, then map HA entities. PowerFlo does not speak Modbus, flash firmware or issue inverter commands. Leave the battery's existing BMS CAN/master-slave arrangement untouched.

2. Wiring and safety gate

Use the inverter manufacturer's shutdown/lockout procedure and a qualified installer. Do not open energised power compartments or work near PV, AC or battery conductors. Confirm the exact board marking/revision before connecting. The inverter RS485 port does not supply power to the Waveshare; use a board-rated power source and verify polarity.

3. Firmware and secrets

  1. Download waveshare-readonly.yaml and secrets.example.yaml. Use a trusted local ESPHome Device Builder/CLI environment.
  2. Copy the secrets template to an untracked secrets.yaml and enter your Wi-Fi SSID/password and a unique 32-byte base64 API key. Generate the key locally with openssl rand -base64 32. Never share populated secrets, compiled firmware containing them, site IPs or device serials.
  3. Validate with esphome config waveshare-readonly.yaml; compile with esphome compile waveshare-readonly.yaml. Validation is not a successful firmware build or live hardware test.
  4. First flash over USB using a data cable, with the inverter bus disconnected. Verify board boot, logs and encrypted HA API before connecting RS485.
  5. Confirm inverter bus address and serial settings on site. The candidate uses address 1, 9600 baud, 8N1 and a conservative 30-second poll; these are commissioning defaults, not automatic detection.

The profile uses ESP-IDF, no serial logging on the RS485 UART, native API encryption and encrypted OTA (ESPHome 2026.9+). It has no Modbus switch/number/write entities, no API-disconnect inverter-setting automation, no fallback access point and no web server. OTA updates the gateway firmware only; do not flash an inverter. Restrict gateway network access to trusted HA/maintenance hosts; do not expose TCP 6053 or firmware update access to the internet.

5. Home Assistant and PowerFlo mapping

Add the ESPHome gateway through HA's ESPHome integration using its API key. Reserve its IP locally. Map watts (not kW), percentage SOC and explicit connectivity. Set actual inverter rating, battery kWh and solar kWp in the card editor. Numeric measurement sensors use force_update so unchanged poll results refresh frontend timestamps. The revised 90-second heartbeat requires recent PV1/2/3, SOC, battery-power, grid-power and load-candidate responses. One successful PV read is not enough. Binary/status entities may publish transitions only: an old last-change timestamp is not itself a stale link. Heartbeat coverage does not certify register semantics; review Recorder retention because forced numeric reports add rows.

6. Commissioning acceptance record

  1. Identity: record model suffix, board revision, firmware, bus address and profile version privately; never post serials or secrets.
  2. Read-only: audit config for writes, disconnect automations, controls and exposed web/AP services. Confirm another RS485 master is not competing.
  3. Electrical: installer signs off communication port, pair continuity, isolation, supply and termination.
  4. Telemetry: compare SOC/V/W/A, grid import, protected load and each PV channel to the display. Capture charge/discharge sign and scale checks. Do not commission by screenshots alone.
  5. Connection: verify explicit grid state in an installer-supervised operating test. Do not simulate a physical outage by unplugging live power wiring. The demo Off-Grid option is a software illustration only.
  6. Freshness: with safe communications access, interrupt RS485 and confirm heartbeat goes off, arrows stop, ETA becomes unavailable and outage coverage is marked unknown rather than a utility outage.
  7. Resilience: take HA offline and confirm inverter settings/operation are unchanged; restore monitoring and verify readings/history recover.
  8. History: compare known counter deltas, inspect HA Statistics metadata, and verify no impossible kWh resets/spikes. Outage/energy gaps must not become zero.
  9. Estimates: compare runtime/ranges to observed behavior; efficiency, future load, solar and taper remain assumptions. Opt into learned taper only after checking its qualified sample basis.

Release readiness and physical commissioning are separate. Keep the inverter's own protection/BMS authoritative; PowerFlo is not a safety controller. Battery expansion requires installer review of DC protection/cabling/BMS compatibility and updating configured capacity—it does not increase inverter current limits or create per-battery telemetry from aggregate Modbus registers.

7. Troubleshooting and rollback

No reads: check dedicated RS485 port, address, 9600 8N1, GPIOs, USB boot/logs and pair continuity with equipment isolated. Intermittent reads: check competing masters, routing and termination. Implausible values: stop relying on the affected channel and compare raw words/scales/firmware; do not repair by writing registers. Wrong arrow direction: correct card sign configuration only after a known-condition comparison.

Rollback the card by installing both files from a prior release and changing the resource version; rollback gateway firmware only using a known-safe read-only build. Keep your private secrets backup secure. Never merge old unsanitized Git history into the public repository.
