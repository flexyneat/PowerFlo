The zero battery-version field neither proves absent BMS communication nor identifies battery firmware. Protocol 0201 is not a register address, baud rate or proof of decoding scale. Logic decision: retain the existing read-only decoding candidates and PowerFlo freshness/unknown-state safeguards. Do not auto-select scales, status bits or relay meanings from this firmware string. Obtain the manufacturer's exact register sheet or timestamp-matched raw-register/display readings for static, charging and discharging states, then validate SOC, V/A/W, grid import/export, protected load and each installed MPPT. Leave uncertain optional fields unmapped. Repeat the comparison after inverter firmware changes; do not request another screenshot as a substitute for live evidence.

1. Understand the data path

The board is a programmable ESP32-S3, not an Ethernet Modbus gateway. Install ESPHome, use its native API over Wi-Fi, then map HA entities. PowerFlo does not speak Modbus, flash firmware or issue inverter commands. Leave the battery's existing BMS CAN/master-slave arrangement untouched.

2. Wiring and safety gate

Use the inverter manufacturer's shutdown/lockout procedure and a qualified installer. Do not open energised power compartments or work near PV, AC or battery conductors. Confirm the exact board marking/revision before connecting. The inverter RS485 port does not supply power to the Waveshare; use a board-rated power source and verify polarity.

3. Firmware and secrets

Commissioning correction: current source applies raw × 0.1 − 100 °C to battery/AC/DC temperatures; the previous source omitted the offset. Compare simultaneous display/readings after flashing; old Recorder data are not repaired. Register-178 Load power is exposed by default as a diagnostic, not certified Protected load. Existing HA-disabled entities may need manual enabling. New raw register-59 status and register-194 relay candidates are isolated read-only diagnostics, not decoded operating-state/grid-availability entities. Seven response-age diagnostics identify missing/delayed heartbeat channels without weakening the strict 90-second freshness gate. No automatic firmware upload or inverter-setting change is performed. These additions require a privately compiled update and live acceptance before PowerFlo flow/estimate integration.

  1. Download waveshare-readonly.yaml and secrets.example.yaml. Use a trusted local ESPHome Device Builder/CLI environment.
  2. Copy the secrets template to an untracked secrets.yaml and enter your Wi-Fi SSID/password and a unique 32-byte base64 API key. Generate the key locally with openssl rand -base64 32. Never share populated secrets, compiled firmware containing them, site IPs or device serials.
  3. Validate with esphome config waveshare-readonly.yaml; compile with esphome compile waveshare-readonly.yaml. Validation is not a successful firmware build or live hardware test.
  4. First flash over USB using a data cable, with the inverter bus disconnected. Verify board boot, logs and encrypted HA API before connecting RS485.
  5. Confirm inverter bus address and serial settings on site. The candidate uses address 1, 9600 baud, 8N1 and a conservative 30-second poll; these are commissioning defaults, not automatic detection.

The profile uses ESP-IDF, no serial logging on the RS485 UART, native API encryption and encrypted native OTA (ESPHome 2026.9+). It contains no Modbus switch/number/write entities or API-disconnect inverter-setting automation. Recovery Wi-Fi and the local web server manage the gateway only. Restrict access to trusted HA/maintenance hosts; never expose TCP 80, TCP 6053, the recovery network or firmware-update access to the internet.

Recovery hotspot and local web diagnostics

Add the three new secret fields from the updated secrets.example.yaml to your private secrets.yaml: deye_gateway_ap_password, deye_gateway_web_username and deye_gateway_web_password. Use different, unique random AP/web passwords of at least 20 characters (AP accepts 8–63). Do not reuse your main Wi-Fi password or commit populated secrets.

If normal Wi-Fi cannot connect, the protected deye-12k-modbus Recovery hotspot starts after 90 seconds (its name follows device_name). Join using the AP password, then open http://192.168.4.1/ if the captive portal does not appear automatically. Correct Wi-Fi settings there and also update your private YAML/secrets so a later flash does not restore old credentials. The hotspot is for recovery, not a permanent second network. Keep a USB data cable as an independent last-resort recovery path.

On the normal LAN, open http://<gateway-IP>/. The web server requires Digest authentication using the web username/password. Version 3 embeds its assets, so no internet is needed at runtime; the build may download those assets. Internal entities are hidden and web log streaming is disabled. This profile exposes sensors/diagnostics only. Digest is not HTTPS: it does not encrypt telemetry or the full HTTP session. Native API/OTA encryption does not protect HTTP; keep it on a trusted, access-restricted network.

Firmware-upload boundary: web_server.ota: false disables regular web firmware upload while the recovery portal is inactive. The captive portal automatically enables recovery firmware upload while active; not every web update path is disabled. During recovery, treat every reachable gateway HTTP interface as administrative: the portal is not explicitly restricted to the AP interface, and its Wi-Fi configuration route bypasses web authentication. Do not rely on AP-only isolation; restrict network access and keep both recovery and web credentials private. Replacing gateway firmware could remove read-only safeguards, so use only your own verified build. Never upload inverter firmware here.

Existing Wi-Fi/API reboot timeouts and safe mode are unchanged. A web browser is not an API client: if HA/API clients remain disconnected, the native API's default timeout can still restart the gateway. This is not an inverter command. Indefinite standalone web operation would need a separately reviewed API reboot-timeout change.

Build verified: the recovery-enabled configuration passed YAML validation and full ESP32-S3 compilation with ESPHome 2026.9.1 / ESP-IDF 5.5.5 using isolated dummy secrets. Reported application size: 907,163 bytes; static RAM: 105,747 bytes. This is not a live recovery test.

Not flashed: validation builds use isolated dummy secrets. Physical acceptance must test normal Wi-Fi and encrypted API, missing Wi-Fi triggering the protected AP, wrong/correct web credentials, page operation without internet, recovery back to the LAN, and the absence of regular web firmware upload with the portal inactive. Verify access restrictions on every reachable interface while the captive portal is active. Never publish a credential-bearing or validation-only binary.

5. Home Assistant and PowerFlo mapping

Add the ESPHome gateway through HA's ESPHome integration using its API key. Reserve its IP locally. Map watts (not kW), percentage SOC and explicit connectivity. Set actual inverter rating, battery kWh and solar kWp in the card editor. Numeric measurement sensors use force_update so unchanged poll results refresh frontend timestamps. The revised 90-second heartbeat requires recent PV1/2/3, SOC, battery-power, grid-power and load-candidate responses. One successful PV read is not enough. Binary/status entities may publish transitions only: an old last-change timestamp is not itself a stale link. Heartbeat coverage does not certify register semantics; review Recorder retention because forced numeric reports add rows.

The card editor also offers optional AC/DC temperature, L2 register voltage, separate inverter output, explicitly unvalidated external-CT candidate, separate daily battery-charge/grid-export and lifetime energy mappings. See README → Waveshare sensor mapping coverage. These readings appear inside System insights, not as additional topology cards. Counter snapshots retain report dates and do not manufacture Week/Month energy; choose compatible Recorder sum statistics separately. The L2 entity name does not establish a second physical phase on this single-phase model. Inverter output is not automatically Protected load. No firmware changes are required merely to add these dashboard mappings.

6. Commissioning acceptance record

  1. Identity: record model suffix, board revision, firmware, bus address and profile version privately; never post serials or secrets.
  2. Read-only: audit config for writes, disconnect automations, controls and exposed web/AP services. Confirm another RS485 master is not competing.
  3. Electrical: installer signs off communication port, pair continuity, isolation, supply and termination.
  4. Telemetry: compare SOC/V/W/A, grid import, protected load and each PV channel to the display. Capture charge/discharge sign and scale checks. Do not commission by screenshots alone.
  5. Connection: verify explicit grid state in an installer-supervised operating test. Do not simulate a physical outage by unplugging live power wiring. The demo Off-Grid option is a software illustration only.
  6. Freshness: with safe communications access, interrupt RS485 and confirm heartbeat goes off, arrows stop, ETA becomes unavailable and outage coverage is marked unknown rather than a utility outage.
  7. Resilience: take HA offline and confirm inverter settings/operation are unchanged; restore monitoring and verify readings/history recover.
  8. History: compare known counter deltas, inspect HA Statistics metadata, and verify no impossible kWh resets/spikes. Outage/energy gaps must not become zero.
  9. Estimates: compare runtime/ranges to observed behavior; efficiency, future load, solar and taper remain assumptions. Opt into learned taper only after checking its qualified sample basis.

Release readiness and physical commissioning are separate. Keep the inverter's own protection/BMS authoritative; PowerFlo is not a safety controller. Battery expansion requires installer review of DC protection/cabling/BMS compatibility and updating configured capacity—it does not increase inverter current limits or create per-battery telemetry from aggregate Modbus registers.

7. Troubleshooting and rollback

Phase 2 frontend additions (unreleased): preparedness details reuse the existing aggregate energy model; the independent preparedness_enabled preference hides that view without removing the simulator or either Battery estimate. Optional comparison charts use HA Recorder/energy statistics, not additional gateway registers. Grid export observations require an independently verified physical grid-point power role and configured polarity, fresh numeric/heartbeat data and an explicit connected-grid state. Counts/coverage are live-session only, not a zero-export certification. Standby stays Not assessed unless a dedicated qualified inverter-only idle measurement is mapped and its scope confirmed, or an explicitly labelled manual assumption is entered. No AC/DC residual is called measured standby loss, and overhead is not deducted twice from readiness/runtime. No transport, firmware map, Modbus writes or BMS settings change. See the README for coverage, calendar/DST limitations and commissioning boundaries.

PowerFlo 0.5.0 planning tools: overnight readiness and the what-if simulator use the existing validated aggregate SOC, configured total kWh, protected-load watts and planning reserve; no new Modbus addresses or inverter writes are introduced. The editor-only mapping guide checks units/values but cannot certify physical channel roles or infer connection from zero watts. Record protected-load demand in HA for the optional three-day matching-time profile; sparse history uses an explicitly labelled manual/recent/current fallback. Verify actual capacity after expansion and keep the BMS/inverter protections authoritative. See the README for assumptions, HA-local deadlines, coverage and simulation-only controls.

No reads: check dedicated RS485 port, address, 9600 8N1, GPIOs, USB boot/logs and pair continuity with equipment isolated. Intermittent reads: check competing masters, routing and termination. Implausible values: stop relying on the affected channel and compare raw words/scales/firmware; do not repair by writing registers. Wrong arrow direction: correct card sign configuration only after a known-condition comparison.

Rollback the card by installing both files from a prior release and changing the resource version; rollback gateway firmware only using a known-safe read-only build. Keep your private secrets backup secure. Never merge old unsanitized Git history into the public repository.
